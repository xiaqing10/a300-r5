## M4 — 超声波倒车停障

**目标**：建立后向感知能力，将 `reverse_allowed` 由硬禁改为**条件性允许**（`REVIEW.md` P1-3）。

**交付物**

1. **硬件**：2~4 路超声波传感器，后向布置，覆盖后方 ≥ 2 m
2. **驱动节点**：`a300_ultrasonic`（新包），发布 `/range/rear_left`、`/range/rear_right`（`sensor_msgs/Range`）、`/ultrasonic/state`
3. **融合逻辑**：`min_valid()` 最小值融合 + 0.5 s 时间戳有效性检查
4. **倒车安全逻辑**：独立阈值集 `rear_stop_distance=0.30` / `rear_slow_distance=0.60` / `rear_max_speed=0.30`
5. **降级策略**：`reverse_permitted = reverse_allowed ∧ ultrasonic_healthy`
6. 新增状态 `REAR_STOP`、`REAR_SENSOR_INVALID`

**验收标准**

| 编号 | 标准 |
|---|---|
| AC-M4-1 | 后方 0.30 m 处放置障碍物，倒车指令被阻止，`/cmd_vel` 的 `linear.x` 归零 |
| AC-M4-2 | 后方 0.60 m 处放置障碍物，倒车速度按比例衰减 |
| AC-M4-3 | 倒车速度不超过 `rear_max_speed`（0.30 m/s） |
| AC-M4-4 | **拔掉超声波传感器**后，倒车能力被自动禁止（fail-safe 生效） |
| AC-M4-5 | 超声波恢复正常后，倒车能力自动恢复 |
| AC-M4-6 | 前方障碍与后方障碍同时存在时，两个方向的约束同时生效且互不干扰 |
| AC-M4-7 | 超声波能检测到 LiDAR 扫描平面**以下**的障碍物（验证盲区补全的实际效果） |

## M5 — 底盘运动控制层

**目标**：实现真机差速运动学与里程计，打通"速度指令 → 轮速"链路。

**交付物**

1. `a300_base_controller` 补齐包骨架（`package.xml` + `CMakeLists.txt`，修复 P1-8）
2. 差速正解（`v, ω → ω_L, ω_R`）与反解（用于里程计）
3. 约束处理链：轮速饱和 → 统一比例缩减（保持转向半径）→ 加速度限幅 → 电机死区
4. 输入独立看门狗（与 M1 的 L3 看门狗构成纵深防御）
5. 发布 `/odom`、`/joint_states`
6. 轮径与轮距的实测标定（`DESIGN.md` §5.2）

**验收标准**

| 编号 | 标准 | 验证方法 |
|---|---|---|
| AC-M5-1 | 直线行走 10 m，轨迹横向偏差 < 0.15 m | 地面标记实测 |
| AC-M5-2 | 原地旋转 360°，角度误差 < 5° | 实测 |
| AC-M5-3 | 轮速饱和时**转向半径不变**（比例缩减生效） | 指令超限速度，观察轨迹形状 |

## 附录 B：架构不变量清单（任何改动均不得违反）

1. **`/cmd_vel` 是整车唯一的运动速度出口**，发布者唯一。
2. **符号语义统一**：全链路使用 ROS 标准约定（前 +X、左转 +ω），中间环节禁止符号翻转。
3. **故障必须收敛**：任一单点故障（传感器、上游、通信、电源）均须导致速度收敛到 0 或进入受限可预测状态。
4. **急停不可自动恢复**：必须显式释放。
5. **仿真与真机共用同一份避障/安全算法**，差异仅存在于传感器与底盘驱动两端。
6. **阈值与几何参数以实测为唯一事实来源**，文档、URDF、YAML 三方必须一致。
7. **保守优先的多传感器融合**：同类物理量取最小值，禁止投票或平均。
8. **安全逻辑与 ROS 运行时解耦**，可在无 ROS 环境下单元测试。
